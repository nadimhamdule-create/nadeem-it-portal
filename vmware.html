#001VM not startingIssue-specific

What is this?

VM power-state failure caused by host resources, storage, lock, snapshot or VM configuration.

Common causes

  • Host/cluster resources
  • Datastore full/inaccessible
  • VMDK/snapshot lock
  • VMX/device config
  • HA/admission control

Detailed troubleshooting

Step 1 — Reproduce 'VM not starting' and capture the exact error, scope, timestamp and last known-good time.
Step 2 — VM > Monitor > Tasks and Events: capture exact power-on error.
Step 3 — Check host connected/resources and datastore capacity/files; inspect disk/snapshot/lock if named in error.
Step 4 — VM Edit Settings: verify disks/NICs/portgroups; inspect hostd/vmkernel at timestamp, fix dependency and retry power-on.

Useful commands

#002VMDK lockedIssue-specific

What is this?

VMDK is the VM virtual disk. VMware locks protect a disk from simultaneous writes; a stale/wrong lock can prevent power-on or snapshot operations.

Common causes

  • VM/process on another host
  • Stale world
  • Backup hot-add/snapshot
  • Storage/APD event
  • Manual file operation

Detailed troubleshooting

Step 1 — Reproduce 'VMDK locked' and capture the exact error, scope, timestamp and last known-good time.
Step 2 — vCenter > VM > Tasks/Events: capture exact lock error and datastore/host.
Step 3 — Confirm VM is not running elsewhere; run vmfsfilelockinfo -p <vmdk> to identify lock owner.
Step 4 — On owning host check esxcli vm process list and backup/snapshot tasks/logs; clear only the stale owner/process, never delete VMDK/delta blindly.

Useful commands

vmfsfilelockinfo -p /vmfs/volumes/<datastore>/<vm>/<disk>.vmdk esxcli vm process list

Verify resolution

Repeat the original 'VMDK locked' workflow. Confirm success from the user side and confirm the corresponding service/event/audit log no longer records the same failure.
